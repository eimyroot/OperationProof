# Contributing

Thanks for contributing to OperationProof.

- Open an issue for substantial protocol, trust-boundary, schema, or architectural changes.
- Keep changes narrowly scoped and preserve fail-closed behavior.
- Never commit credentials, secrets, production data, or sensitive evidence.
- Changes to identity, authorization, provenance, attestations, verification, or execution boundaries require explicit tests and rationale.

Use the development and test commands documented in the repository. Run the relevant test matrix before opening a pull request.

Pull requests should explain what changed, why, how it was tested, and any compatibility, security, migration, or trust-model impact.

By contributing, you agree that your contribution is submitted under the repository's existing license and project terms once the repository license is adopted on the default branch, unless a separate written agreement applies.
